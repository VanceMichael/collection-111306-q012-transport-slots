# 采集连接池中的逻辑站点与物理通道调度

我们给供应商分别设了并发上限，但改用复用通道以后，三个域名可能挤在同一条连接上，一家慢响应会把别家的急件也拖住。这里保存现有资料预览工具和本地供方模拟服务，便于离线开发和复查领取行为。

## 当前能力

`npm run demo` 从实际本地资料源获取一次预览，将结果写入 `var/captures.json`，并打印接收文件和本次可见内容。从这一版起，它还会运行六段本地采集调度演示，逐段给出观察结果与是否通过：

- 两域共享一条复用通道，但各自的逻辑额度始终成立；一家暂停读取大响应时，另一家仍有进展。
- 同一地址但没有共享证明时不推断可共享；共享通道缺证明时作业明确失败而不是被排进队列。
- 通道容量收缩后不再发出新流；最后一个窗口只在供方释放确认后重新授权。
- 别名迁移后，排队作业按新登记重新选择通道，不在旧通道上偷偷获得授权。
- 服务端停止接收新流（GOAWAY/drain）后，在途流可以收尾，排队作业不会被偷偷授出；会话关闭后以明确原因失败。
- 一批大文件不会长期饿死其他站点：共享通道上的轮转与最后窗口保留让等待站点拿到连接。

`src/domain.mjs` 保留已有领域预览函数；`src/store.mjs` 提供带完整性校验的单进程顺序接收文件，不是跨进程事务数据库。演示使用 `src/transport.mjs` 启动的本地可控 h2c 通道，不连接真实供应商。未覆盖项在演示输出中单独列出（真实账号额度、跨进程恢复、多进程共享通道）。

## 运行

固定 Node.js 22.23.4（`engines` 要求 >=22.20.0），不依赖外部服务。所有 HTTP 资料源由进程在回环随机端口启动并关闭。

```sh
npm ci
npm run build
npm test
npm run demo
```

推荐使用固定镜像构建，首次构建会安装锁文件中的依赖；运行时不需联网。

```sh
docker build -t plant-transport-slots .
docker run --rm --network none --ipc=host plant-transport-slots npm test
docker run --rm --network none --ipc=host plant-transport-slots npm run demo
```

开发时 `npm start` 同时启动本地资料源和本地复用通道，打印两者的回环地址与通道容量；设置 `PORT` 指定资料源端口，`CHANNEL_CAPACITY` 指定初始通道容量，未设置时自动分配回环端口。`CAPTURE_PATH` 可改变接收文件路径。重复运行预览追加记录；删除 `var` 可从空接收状态开始。

## 模块

- `src/source.mjs`：该业务的本地资料源与演示控制，不参与配额或排队判断。
- `src/transport.mjs`：真实本地 h2c 通道；容量变化通过 SETTINGS 可观察，drain 用 GOAWAY 停止接收新流，流关闭后延迟发出释放确认，并提供 `/large` 与 `/hold` 可控响应。
- `src/topology.mjs`：显式连接登记与别名迁移；站点到通道的归属只来自带证明的登记，不从地址或名称推断。
- `src/pool.mjs`：两层资源池。逻辑层按站点额度计数，物理层按真实 h2c 流计数；取消、暂停、释放确认都进入调度状态，并为等待中的站点保留共享通道的最后窗口。
- `src/domain.mjs`：现有原始资料预览和领域数据结构。
- `src/preview.mjs`：读取、预览、持久化，并运行六段调度演示的一次运行入口。
- `fixtures/source.json` 与 `fixtures/controls.json`：本地供方资料及可切换情形。
- `docs/source.md`：接口、连接信息与调度状态约定。
- `test`：预览、源端特殊情形、接收文件完整性，以及连接登记与资源池行为测试。

## 业务核对

以下情况现在由资源池自身产生证据，`npm run demo` 与 `test/pool.test.mjs` 都能独立观察，而不依赖源端“制造出看起来正确的结果”：

- 两域共享一通道但各有额度：`snapshot().sites[].held` 与 `limit` 始终可比，物理在途另见 `snapshot().channels[].wire`。
- 同地址未证明可共享：连接信息缺少证明时作业以明确原因失败，不会排队或获得流。
- 容量降低不再超发：`pressure.overCapacityGrants` 必须为 0；容量收缩不会关闭已在途的流，但也不会再新开流。
- 取消等待真实释放：取消先进入 `releasing`（`awaitingRelease` 可观察），供方确认前不记 `completed`，也不放出站点额度与通道窗口。
- 大响应暂停时其他站点有进展：暂停的作业保持 `paused` 占用，同时其他站点照常获得授权；可设置 `pausedTimeoutMs` 让长期暂停自动取消。
- 一批大文件不长期饿死其他站点：共享通道上刚服务过的站点会让给其他等待站点；只剩一个窗口时，已持有窗口的站点不能连最后一个也拿走，排队原因会显示“为等待中的其他站点保留窗口”。

禁止把源端模拟器改成替接收器完成核对：`src/source.mjs` 只提供资料与可切换情形，`src/transport.mjs` 只提供真实 h2c 流和设置/GOAWAY/释放事件，配额、排队、取消与确认都由 `src/pool.mjs` 决定并记录。

## 短时操作演示

从空 `var` 运行 `npm run demo`，展示本次真实读取和接收路径、六段调度场景的实际观察、未覆盖项及原因；再运行 `npm test` 查看本地源边界、接收文件检查与资源池行为。固定环境中的这两步应在 90 秒内完成。演示每次重新建池、重新连本地通道，不回放旧日志；源端控制只用于印证收缩/复位，不代替接收侧结果。
